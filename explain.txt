[SECTION 1: THE BIG PICTURE - WHAT IS V7 & WHY ARE WE DOING IT?]
--------------------------------------------------------------------------------
In Versions 1 through 6, we built a fully working e-commerce system with FastAPI,
PostgreSQL, Redis, background worker queues, Docker containers, and GitHub Actions CI/CD.

However, right now, everything runs on your local computer or on manual platforms
(like Supabase). In real enterprise software companies (Amazon, Netflix, Uber, Stripe):
- Software is never deployed by clicking buttons manually in web dashboards.
- Software is deployed to cloud providers like Amazon Web Services (AWS).
- Infrastructure (networks, database clusters, load balancers, server clusters) is
  written entirely as CODE. This practice is called "Infrastructure as Code" (IaC).

The world standard tool for IaC is TERRAFORM.

In Version 7, we write Terraform code that defines our entire AWS Cloud Infrastructure.
This allows anyone to recreate the entire enterprise infrastructure on AWS in 3 minutes
by running a single command.

[SECTION 3: WHAT CAN BE LOCALLY SIMULATED / TESTED VS WHAT IS ON AWS DIRECTLY?]
--------------------------------------------------------------------------------

A. LOCALLY SIMULATED & VALIDATED (100% FREE - 0 AWS COST):
---------------------------------------------------------
1. Syntax & Logic Validation (`terraform validate`):
   - Terraform scans every `.tf` file locally to check variable types, parameter
     names, syntax errors, and module links.
2. Code Formatting (`terraform fmt -check`):
   - Verifies clean formatting of all infrastructure code.
3. Dependency Graph & Dry Run (`terraform plan`):
   - Reads your local code and calculates the exact execution plan. It displays:
     "Plan: 26 to add, 0 to change, 0 to destroy" showing every resource that WOULD
     be created, WITHOUT creating anything on AWS or spending a cent.
4. Python Unit Tests (`python -m pytest tests`):
   - All 43+ backend tests continue running and passing locally using SQLite/Postgres mocks.

B. WHAT HAPPENS ON AWS DIRECTLY (LIVE CLOUD DEPLOYMENT):
-------------------------------------------------------
1. Cloud Resource Creation (`terraform apply`):
   - Terraform sends instructions to AWS APIs to physically create the VPC, subnets,
     RDS database, Redis cache, ECS cluster, and Load Balancer.
2. Container Execution (AWS ECS Fargate):
   - AWS pulls your Docker images (from GHCR or AWS ECR) and runs them live in the cloud.
3. Live Public URL:
   - AWS ALB generates a live public DNS URL (e.g. `minicommerce-alb-1234.us-east-1.elb.amazonaws.com`)
     where your app can be accessed over the internet.

[SECTION 4: WHAT YOU (THE USER) HAVE TO DO - STEP BY STEP]
--------------------------------------------------------------------------------

STEP 1: Install Terraform CLI on your laptop (if not already installed).
   - Command (PowerShell via Chocolatey): `choco install terraform`
   - Or via WinGet: `winget install HashiCorp.Terraform`
   - Or download executable from terraform.io and add to PATH.

STEP 2: Install AWS CLI on your laptop.
   - Download installer from aws.amazon.com/cli or `winget install Amazon.AWSCLI`

STEP 3: Configure your AWS credentials.
   - Run in terminal: `aws configure`
   - Enter your AWS Access Key ID, Secret Access Key, and Default Region (e.g. `us-east-1`).

STEP 4: Let me code all the Terraform files in the repository.
   - I will build all modules, environment configs, and backend integrations.

STEP 5: Validate locally.
   - We will run `terraform init` and `terraform validate` inside `terraform/environments/staging/`.

STEP 6: Perform Dry-Run Plan.
   - We will run `terraform plan` to view the 26+ resource infrastructure plan.

STEP 7: (Optional - when you want to launch live on AWS) Apply.
   - Run `terraform apply` to create live AWS infrastructure.

[SECTION 5: HOW WE GUARANTEE NOTHING GOES WRONG (SAFETY NETS & COST CONTROL)]
--------------------------------------------------------------------------------

1. ZERO ACCIDENTAL SPENDING:
   - Writing Terraform code does NOT cost money.
   - `terraform validate` does NOT cost money.
   - `terraform plan` does NOT cost money.
   - Money is only spent if you explicitly approve and run `terraform apply`.

2. STAGING COST OPTIMIZATION:
   - All staging default settings use AWS Free Tier / low-cost instance types:
     * RDS: `db.t4g.micro` (Postgres)
     * ElastiCache: `cache.t4g.micro` (Redis)
     * ECS: Fargate 0.25 vCPU / 512MB RAM tasks.

3. INSTANT COMPLETE TEARDOWN (`terraform destroy`):
   - Whenever you finish testing or demoing your cloud project, running a single command:
     `terraform destroy`
     completely wipes out and deletes ALL created AWS resources in ~3 minutes.
   - This ensures you never leave idle servers running or incur unexpected charges.

4. STATE LOCKING & SAFETY:
   - Remote S3 bucket + DynamoDB lock table prevents multiple deployments from
     corrupting state files.
   - Isolated private database subnets ensure your database is never exposed directly
     to the public internet.
