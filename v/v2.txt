Welcome to MiniCommerce Version 2 (V2) — a dedicated Database Engineering, Concurrency & Performance Laboratory. 

V1 established a clean 4-tier FastAPI backend (Routers → Services → Models → PostgreSQL). 
V2 shifts focus to database engineering under load and modern frontend component engineering:
1. 5-Tier Data Layer Architecture (introducing the Repository Pattern in app/repositories/)
2. Concurrency Control & Pessimistic Row-Level Locking (SELECT ... FOR UPDATE with deterministic ID ordering)
3. Idempotency Engine (Idempotency-Key header backed by composite UNIQUE constraint on orders table)
4. Catalog Pagination, Price Filtering, Category Chips & Real-time Search (OFFSET pagination on GET /api/v1/products)
5. Standardized Error Payload Formatting (app/core/errors.py)
6. High-Speed Bulk Seeding (generate_load_data.py generating 409,913 records in Supabase PostgreSQL)
7. Modern React 18 + Vite 5 SPA Frontend (frontend/) with Lucide Icons and Dark Glassmorphism Design System
8. EXPLAIN ANALYZE Benchmarking & Technical Documentation Laboratory (docs/v2/)

STRICTLY EXCLUDED IN V2 (Reserved for V3+): Redis, Docker, Celery, Kafka, AWS, Kubernetes, Microservices.

SECTION 2: ENGINEERING DECISIONS & DESIGN TRADE-OFFS
================================================================================

1. **React 18 + Vite 5 SPA Frontend Architecture**:
   - *Decision*: Rebuild `frontend/` using **React 18**, **Vite 5**, and **Lucide React Icons**.
   - *Rationale*: Replaces basic vanilla HTML with a modular component architecture (`Navbar`, `CategoryBar`, `ControlBar`, `ProductCard`, `ProductGrid`, `CartDrawer`, `AuthModal`, `Pagination`, `Toast`). Lightning-fast Hot Module Replacement (HMR) via `npm run dev`.

2. **Repository Pattern Encapsulation**:
   - *Decision*: Introduce `app/repositories/` containing pure data-access static methods.
   - *Rationale*: Routers handle HTTP parsing; Services handle business rules and transaction boundaries; Repositories isolate SQLAlchemy select/update constructs.

3. **Pessimistic Row-Level Locking (`SELECT FOR UPDATE`)**:
   - *Decision*: Lock product rows explicitly during checkout using `ProductRepository.get_by_ids_for_update`.
   - *Rationale*: Prevents race conditions and lost updates when multiple users purchase the last remaining stock (`stock = 1`) simultaneously.

4. **Deterministic Lock Ordering (`ORDER BY id ASC`)**:
   - *Decision*: Sort product IDs in ascending order (`sorted(product_ids)`) before querying `with_for_update()`.
   - *Rationale*: Eliminates cyclic wait deadlocks when concurrent transactions request overlapping sets of products in different order.

5. **Composite Unique Database Constraint for Idempotency**:
   - *Decision*: Enforce idempotency at the PostgreSQL database level using `UniqueConstraint("user_id", "idempotency_key")`.
   - *Rationale*: Application-level checks can be bypassed by simultaneous parallel requests. Database unique constraints provide absolute transactional guarantees.

6. **Catalog Search & Category Filtering (`ILIKE` Matching)**:
   - *Decision*: Add optional `search` (text search matching `Product.name` and `Product.description`) and `category` query parameters to `GET /api/v1/products`.
   - *Rationale*: Enables instant full-text filtering across the 50,000 product benchmark dataset directly from the UI.

7. **Configurable Page Size (12, 24, 48, 96 per page)**:
   - *Decision*: Expose configurable page size controls in `ControlBar.jsx` and forward `page_size` parameter to the backend.
   - *Rationale*: Replaces rigid 6-item pagination with user-selectable density while maintaining OFFSET bounds.

8. **`X-Total-Count` Header & Unconstrained Page Scrolling**:
   - *Decision*: Attach `X-Total-Count` response header on `GET /api/v1/products` and remove `overflow: hidden` from body CSS (`overflow-y: auto !important`).
   - *Rationale*: Provides frontend pagination components with total page numbers while enabling smooth vertical scrolling.

9. **Outermost CORSMiddleware Position**:
   - *Decision*: Position `CORSMiddleware` as the outermost middleware (added last in `main.py`).
   - *Rationale*: Guarantees CORS headers (`Access-Control-Allow-Origin: *`, `Access-Control-Expose-Headers: X-Total-Count`) are attached to all response types, including 4xx/5xx exceptions.

10. **Client-Side Python UUID Pre-generation for Bulk Seeding**:
   - *Decision*: Assign `uuid.uuid4()` client-side in `generate_load_data.py` before `db.add_all()`.
   - *Rationale*: Eliminates `RETURNING id` network round-trips (`db.refresh()`), allowing 409,913 records to seed in under 60 seconds over remote Supabase pooler connections.

### 1. Backend Search, Category & Pagination Query (`app/repositories/product_repository.py`)
```python
@staticmethod
async def list_products(
    db: AsyncSession,
    page: int = 1,
    page_size: int = 20,
    min_price: Decimal | None = None,
    max_price: Decimal | None = None,
    sort_by: str = "name",
    sort_order: str = "asc",
    search: str | None = None,
    category: str | None = None
) -> tuple[list[Product], int]:
    stmt = select(Product)

    if search:
        search_term = f"%{search.strip()}%"
        stmt = stmt.where(
            (Product.name.ilike(search_term)) | (Product.description.ilike(search_term))
        )

    if category and category.lower() != "all":
        cat_term = f"%{category.strip()}%"
        stmt = stmt.where(
            (Product.name.ilike(cat_term)) | (Product.description.ilike(cat_term))
        )

    if min_price is not None:
        stmt = stmt.where(Product.price >= min_price)
    if max_price is not None:
        stmt = stmt.where(Product.price <= max_price)

    count_stmt = select(func.count()).select_from(stmt.subquery())
    total_result = await db.execute(count_stmt)
    total_count = total_result.scalar_one() or 0

    valid_sort_fields = {
        "name": Product.name,
        "price": Product.price,
        "created_at": Product.created_at,
        "stock": Product.stock
    }
    sort_column = valid_sort_fields.get(sort_by.lower(), Product.name)
    direction = desc if sort_order.lower() == "desc" else asc

    stmt = stmt.order_by(direction(sort_column))
    offset = (page - 1) * page_size
    stmt = stmt.offset(offset).limit(page_size)

    result = await db.execute(stmt)
    products = list(result.scalars().all())
    return products, total_count
```

### 2. Products Router with `X-Total-Count` Header (`app/api/v1/products.py`)
```python
@router.get("", response_model=list[ProductResponse])
async def list_products(
    response: Response,
    page: int = Query(1, ge=1),
    page_size: int = Query(20, ge=1, le=100),
    min_price: Decimal | None = Query(None, ge=0),
    max_price: Decimal | None = Query(None, ge=0),
    sort_by: str = Query("name"),
    sort_order: str = Query("asc"),
    search: str | None = Query(None),
    category: str | None = Query(None),
    db: AsyncSession = Depends(get_db)
):
    products, total_count = await ProductService.list_products(
        db, page=page, page_size=page_size, min_price=min_price, max_price=max_price,
        sort_by=sort_by, sort_order=sort_order, search=search, category=category
    )
    response.headers["X-Total-Count"] = str(total_count)
    response.headers["Access-Control-Expose-Headers"] = "X-Total-Count"
    return products
```

### 3. React Atomic Idempotent Checkout (`frontend/src/App.jsx`)
```javascript
const handleCheckout = async () => {
  if (!cart?.cart_items || cart.cart_items.length === 0) {
    showToast('error', 'Empty Cart', 'Please add products to your cart before checking out.');
    return;
  }

  setIsCheckingOut(true);
  const idempotencyKey = `idemp_${Date.now()}_${Math.random().toString(36).substring(2, 9)}`;

  try {
    const { data: order } = await apiRequest(
      '/orders',
      'POST',
      null,
      true,
      { 'Idempotency-Key': idempotencyKey }
    );

    setCart({ cart_items: [] });
    setIsCartOpen(false);
    await fetchProducts();

    showToast(
      'success',
      '⚡ Atomic Checkout Confirmed!',
      `Order confirmed with Idempotency-Key: ${idempotencyKey}. Total: $${parseFloat(order.total_amount).toFixed(2)}`,
      order.id
    );

  } catch (err) {
    showToast('error', 'Checkout Execution Failed', err.message);
  } font-finally {
    setIsCheckingOut(false);
  }
};
```

SECTION 7: ERROR LOG & RESOLUTION TRACKER
================================================================================

[ERROR 1: KEYERROR ON 'DETAIL' IN PYTEST ASSERTIONS]
- Symptom: 5 test cases in `test_auth.py`, `test_cart.py`, `test_orders.py`, `test_products.py` failed with `KeyError: 'detail'`.
- Root Cause: Custom exception handler returned `{"error": {"code": ..., "message": ...}}` without root `"detail"` key.
- Solution: Updated `app/core/errors.py` to include both `"detail"` and `"error"` in JSON response payload.

[ERROR 2: SQLALCHEMY MISSINGGREENLET DURING EXPIRE_ALL()]
- Symptom: Pytest raised `sqlalchemy.exc.MissingGreenlet: greenlet_spawn has not been called; can't call await_only() here`.
- Root Cause: Invoking `db_session.expire_all()` expired `product.id` attribute, triggering synchronous lazy loading when passed to `ProductRepository.get_by_id(db_session, product.id)`.
- Solution: Extracted primitive UUID `product_id = product.id` into a local variable prior to calling `db_session.expire_all()`.

[ERROR 3: TEST SESSION CROSS-CONTAMINATION IN PYTEST ASYNC CLIENT]
- Symptom: Concurrent requests in `test_concurrency.py` interfered with each other's transactions on SQLite.
- Root Cause: `conftest.py` `client` fixture yielded a single `db_session` object shared across concurrent HTTP requests.
- Solution: Updated `conftest.py` `client` fixture to yield a fresh `TestSessionLocal()` database session per request.

[ERROR 4: MISSING COLUMN ON SUPABASE DATABASE]
- Symptom: Seeding script failed with `sqlalchemy.exc.ProgrammingError: column "idempotency_key" of relation "orders" does not exist`.
- Root Cause: `Base.metadata.create_all` only creates new tables and does not alter existing tables from V1.
- Solution: Created `app/db/migrate_idempotency.py` executing `ALTER TABLE orders ADD COLUMN IF NOT EXISTS idempotency_key VARCHAR(255);` and unique index creation.

[ERROR 5: UNICODEENCODEERROR ON WINDOWS POWERSHELL CONSOLE]
- Symptom: `generate_load_data.py` failed with `UnicodeEncodeError: 'charmap' codec can't encode character '\U0001f680'`.
- Root Cause: Emojis (`🚀`, `📦`) in print statements triggered encoding failure on standard Windows `cp1252` console output.
- Solution: Replaced unicode emojis in `generate_load_data.py` with standard ASCII tags (`[INFO]`, `[PROGRESS]`, `[SUCCESS]`).

[ERROR 6: DUPLICATE KEY VIOLATION ON BENCHMARK USER EMAILS]
- Symptom: Seeding failed with `asyncpg.exceptions.UniqueViolationError: duplicate key value violates unique constraint "ix_users_email"`.
- Root Cause: Static user email pattern `load_user_{i}@benchmark.com` conflicted with users inserted in previous partial runs.
- Solution: Added UUID run prefix `user_{run_id}_{i}@benchmark.com` to guarantee unique email generation on repeat executions.

[ERROR 7: BROWSER "CHECKOUT ERROR: FAILED TO FETCH"]
- Symptom: Frontend displayed `Checkout error: Failed to fetch` toast notification.
- Root Cause: Backend server was un-reachable because `uvicorn` was launched from `frontend/` directory instead of `backend/`, and `CORSMiddleware` was inner to custom middlewares.
- Solution: Launched `uvicorn` from `backend/` and reordered `CORSMiddleware` to be the outermost middleware in `app/main.py`.

[ERROR 8: FRONTEND PAGINATION & UNRESPONSIVE PAGE HEIGHT]
- Symptom: Frontend displayed only 6 items per page without category search or page scroll.
- Root Cause: Legacy HTML layout used static CSS height overflow limits without category or search parameters on backend API.
- Solution: Rebuilt frontend into a React 18 + Vite SPA with Lucide Icons, Category Chips, Search Bar, configurable page size selector (12/24/48/96), `X-Total-Count` headers, and unconstrained body scrolling (`overflow-y: auto !important`).

[ERROR 9: USER EMAIL NOT UPDATING ON LOGIN & CART SYNC STALL]
- Symptom: Signing in with a new email did not update the navbar user email pill, and adding items to cart did not update the cart badge count.
- Root Cause: Backend `/auth/login` endpoint returns `{ access_token, token_type }` without a nested user object, causing `data.user` to evaluate as `undefined`. `ensureAuthenticated` fell back to auto-authenticating as Alice.
- Solution: Updated `AuthModal.jsx` and `App.jsx` to fetch the user profile from `/auth/me` immediately after token acquisition, storing `userProfile` in local storage and React state.
