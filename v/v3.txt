Welcome to MiniCommerce Version 3 (V3) — Containerization, In-Memory Caching & Distributed State Resilience Laboratory.

V1 established a clean 4-tier FastAPI architecture.
V2 established a 5-tier data layer with pessimistic row-level locking (`SELECT FOR UPDATE`), idempotency constraints, and a React 18 SPA.
V3 evolves the project into a multi-container, high-performance distributed laboratory:
1. Multi-Container Topology (`docker-compose.yml` orchestrating `backend`, `redis:7-alpine`, and `frontend` Nginx alpine)
2. Remote Supabase PostgreSQL persistence (409,913 records in AWS Cloud; zero local DB container disk footprint)
3. Async Redis Cache-Aside Layer (`app/core/redis.py`, `app/services/cache_service.py` with ~36x catalog latency speedup: 102ms ➔ 2.8ms)
4. Automatic Cache Write Invalidation on Stock & Order Mutations (`order_service.py` and `product_service.py`)
5. Fault-Tolerance & Resilient Failover (0.2s connection timeout; logs warning and falls back to Supabase DB with 0% 500 error rate when Redis is down)
6. Distributed Health Probes (`/healthz` Liveness & `/readyz` Readiness probe endpoints)
7. Expanded Automated Verification (27/27 passing Pytest suite) & Performance Benchmarking (`docs/v3/`)

1. **Async Redis Connection Pool Lifecycle with Fast 0.2s Failover (`app/core/redis.py`)**:
```python
redis_pool: ConnectionPool | None = None
redis_client: Redis | None = None

async def init_redis_pool() -> None:
    global redis_pool, redis_client
    try:
        redis_pool = ConnectionPool.from_url(
            settings.REDIS_URL,
            decode_responses=True,
            socket_connect_timeout=0.2,
            socket_timeout=0.2
        )
        redis_client = Redis(connection_pool=redis_pool)
        await redis_client.ping()
        logger.info(f"Connected to Redis pool at {settings.REDIS_URL}")
    except Exception as e:
        redis_client = None
        redis_pool = None
        logger.warning(f"Failed to initialize Redis pool on startup: {e}. Falling back to DB-only operations.")
```

2. **Cache-Aside Logic & Pattern Invalidation (`app/services/cache_service.py`)**:
```python
class CacheService:
    @staticmethod
    async def get(key: str) -> Any | None:
        redis = get_redis()
        if not redis: return None
        try:
            val = await redis.get(key)
            return json.loads(val) if val else None
        except Exception as e:
            logger.warning(f"Redis get failed for key '{key}': {e}. Falling back to DB.")
            return None

    @staticmethod
    async def invalidate_pattern(pattern: str) -> int:
        redis = get_redis()
        if not redis: return 0
        deleted_count = 0
        try:
            cursor = 0
            while True:
                cursor, keys = await redis.scan(cursor=cursor, match=pattern, count=100)
                if keys:
                    deleted_count += await redis.delete(*keys)
                if cursor == 0: break
            return deleted_count
        except Exception as e:
            logger.warning(f"Redis invalidation failed for pattern '{pattern}': {e}.")
            return 0
```

3. **Readiness Probe (`app/api/v1/health.py`)**:
```python
@health_router.get("/readyz")
async def readiness_probe(response: Response, db: AsyncSession = Depends(get_db)):
    db_ok, redis_ok = False, False
    try:
        if (await db.execute(text("SELECT 1"))).scalar() == 1: db_ok = True
    except Exception: db_ok = False

    try:
        redis_client = get_redis()
        if redis_client and await redis_client.ping(): redis_ok = True
    except Exception: redis_ok = False

    all_healthy = db_ok and redis_ok
    response.status_code = status.HTTP_200_OK if all_healthy else status.HTTP_503_SERVICE_UNAVAILABLE
    return {
        "status": "ready" if all_healthy else "unready",
        "dependencies": {"database": "connected" if db_ok else "unreachable", "redis": "connected" if redis_ok else "unreachable"}
    }
```

SECTION 6: ERROR LOG & RESOLUTION TRACKER
================================================================================

[ERROR 1: MODULENOTFOUNDERROR: NO MODULE NAMED 'REDIS']
- Symptom: Pytest failed on test collection.
- Root Cause: `redis` package was listed in `requirements.txt` but not installed in the active local virtual environment.
- Solution: Executed `pip install redis` in `.venv`.

[ERROR 2: DOCKER COMPOSE WARNING ON OBSOLETE VERSION ATTRIBUTE]
- Symptom: Warning message `attribute 'version' is obsolete, it will be ignored`.
- Root Cause: `version: '3.8'` tag in top level of `docker-compose.yml` is deprecated in modern Docker Compose V2.
- Solution: Removed `version: '3.8'` line from `docker-compose.yml`.

[ERROR 3: DOCKER COMPOSE UNSET ENVIRONMENT VARIABLE WARNING]
- Symptom: Warning `The "DATABASE_URL" variable is not set. Defaulting to a blank string.`
- Root Cause: `docker-compose.yml` shell interpolation attempted to read `${DATABASE_URL}` from host terminal environment instead of directly reading `backend/.env`.
- Solution: Configured `env_file: ./backend/.env` in `docker-compose.yml` and created root `.env` file.

[ERROR 4: HEALTHCHECK FAILED IN BACKEND CONTAINER]
- Symptom: Backend container healthcheck `curl -f http://localhost:8000/healthz` failed.
- Root Cause: `python:3.12-slim` base image does not include `curl` binary by default.
- Solution: Added `RUN apt-get update && apt-get install -y curl` in `backend/Dockerfile`.

[ERROR 5: LOCAL DEV TIMEOUT DELAY WITHOUT REDIS CONTAINER]
- Symptom: Running backend locally without Redis added a 2-second connection timeout latency per request.
- Root Cause: `socket_connect_timeout` was set to 2.0s, and `redis_client` wasn't set to `None` on failed connection ping.
- Solution: Reduced `socket_connect_timeout` to `0.2s` and explicitly assigned `redis_client = None` on connection failure.
