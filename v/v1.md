# MiniCommerce V1 — Architecture & Implementation Details

Welcome to **MiniCommerce Version 1 (V1)** — a clean backend engineering laboratory built to demonstrate production-grade FastAPI architecture, PostgreSQL database design, SQLAlchemy 2.x ORM, Alembic migrations, JWT authentication, atomic checkout transactions, and modern middleware practices.

---

## 📐 Architecture Specification

MiniCommerce V1 follows a strict 4-tier layered architecture enforcing separation of concerns:

```text
HTTP Request
     │
     ▼
Router Layer (Thin API Controllers)
  ├── backend/app/api/v1/auth.py
  ├── backend/app/api/v1/products.py
  ├── backend/app/api/v1/cart.py
  ├── backend/app/api/v1/orders.py
  └── backend/app/api/v1/router.py
     │
     ▼
Service Layer (Business Logic & Transactions)
  ├── backend/app/services/auth_service.py
  ├── backend/app/services/product_service.py
  ├── backend/app/services/cart_service.py
  └── backend/app/services/order_service.py
     │
     ▼
SQLAlchemy DB Layer (ORM Persistence & Session)
  ├── backend/app/models/ (user.py, product.py, cart.py, order.py)
  └── backend/app/db/ (session.py, base.py, seed.py)
     │
     ▼
PostgreSQL / Supabase Database
```

### Core Layer Rules
1. **Thin Routers**: Route handlers only perform HTTP request validation, dependency injection, and response mapping.
2. **Business Rules in Services**: All domain logic, validation, stock checks, and database transactions belong exclusively in the service layer.
3. **Pydantic Schemas vs ORM Models**: Pydantic schemas (`schemas/`) represent API contracts; SQLAlchemy 2.x declarative models (`models/`) represent database persistence.
4. **No Raw SQL in Routers**: All database operations use SQLAlchemy 2.x async select constructs and ORM sessions.

## ✨ Features Implemented in Version 1

### 1. Database Design & Persistence (PostgreSQL / Supabase)
- **UUID Primary Keys**: `uuid.uuid4()` for secure, non-sequential resource identifiers across all tables.
- **Monetary Precision**: `Numeric(10,2)` used for all monetary amounts (`price`, `total_amount`).
- **Database Tables Implemented**:
  - `users`: `id` (UUID PK), `email` (String(255), unique, indexed), `password_hash`, `created_at`.
  - `products`: `id` (UUID PK), `name`, `description`, `price` (Check `>= 0`), `stock` (Check `>= 0`), `created_at`, `updated_at`.
  - `carts`: `id` (UUID PK), `user_id` (FK users.id, unique 1-to-1), `created_at`, `updated_at`.
  - `cart_items`: `id` (UUID PK), `cart_id` (FK carts.id), `product_id` (FK products.id), `quantity` (Check `> 0`), `UNIQUE(cart_id, product_id)`.
  - `orders`: `id` (UUID PK), `user_id` (FK users.id), `status` (`PENDING`, `CONFIRMED`, `CANCELLED`), `total_amount`, `created_at`.
  - `order_items`: `id` (UUID PK), `order_id` (FK orders.id), `product_id` (FK products.id), `quantity`, `price` (historical purchase price snapshot).

### 2. Supabase PostgreSQL Integration & PgBouncer Compatibility
- Connection via Supabase PgBouncer transaction mode pooler (`aws-0-ap-south-1.pooler.supabase.com:6543`) providing full IPv4 support.
- Password URL-encoding (`@` -> `%40`) ensuring URI compatibility.
- Disabled prepared statement caching (`statement_cache_size=0`) in `app/db/session.py` for PgBouncer compatibility.

### 3. Authentication & Security
- **Direct Bcrypt Hashing**: Implemented `bcrypt.hashpw` and `bcrypt.checkpw` for secure password storage.
- **JWT Token Management**: Encodes and decodes JWT tokens (`sub: user_id`, `exp: expiry_time`).
- **User Dependency**: `get_current_user` in `app/api/deps.py` validates Bearer tokens on protected endpoints.
- Endpoints: `POST /api/v1/auth/register`, `POST /api/v1/auth/login`, `GET /api/v1/auth/me`.

### 4. Products API
- Endpoints: `GET /api/v1/products`, `GET /api/v1/products/{id}`, `POST /api/v1/products`.
- Implemented in `ProductService` with stock validation and pagination/listing.

### 5. Cart Management
- Endpoints: `GET /api/v1/cart`, `POST /api/v1/cart/items`, `PATCH /api/v1/cart/items/{id}`, `DELETE /api/v1/cart/items/{id}`.
- Auto-creates user cart on first access.
- Validates that requested quantity does not exceed product stock.
- Enforces strict user cart ownership isolation.

### 6. Atomic Checkout Transaction
- Endpoint: `POST /api/v1/orders`.
- **Atomic Flow**:
  1. Load authenticated user's cart with eager relationship loading (`selectinload`).
  2. Verify cart is non-empty.
  3. Validate product stock availability. If stock is insufficient, rollback transaction and return `HTTP 409 Conflict`.
  4. Calculate order total and snapshot current product prices.
  5. Create `Order` and `OrderItem` records with price snapshots.
  6. Deduct product stock.
  7. Clear cart items.
  8. Atomically commit transaction. On any failure, execute complete rollback.

### 7. Custom Middleware
- **Request ID Middleware** (`app/middleware/request_id.py`): Reads or generates `X-Request-ID` UUID and attaches header to responses.
- **Logging Middleware** (`app/middleware/logging.py`): Logs `method`, `path`, `status_code`, `latency_ms`, and `request_id`.

### 8. Database Seed Script & Test Suite
- **Seed Script** (`app/db/seed.py`): Executable script creating all database tables and seeding simulated Users (Alice, Bob, Charlie), Products (10 items), Alice's active cart, and Bob's confirmed order history.
- **Pytest Suite** (`tests/`): 17 unit and integration tests achieving 100% pass rate.

### 9. Vanilla JS Frontend SPA
- Responsive modern dark glassmorphism SPA built with HTML5, CSS3, and Vanilla JS (`index.html`, `styles.css`, `app.js`). Includes quick test login shortcuts, product catalog display, stock badges, live cart drawer, atomic checkout button, and order history view.

## 🚀 Quick Execution Commands

```powershell
# Run Seed Script
cd backend
.\.venv\Scripts\python.exe app/db/seed.py

# Run Pytest Suite
.\.venv\Scripts\python.exe -m pytest -v

# Run FastAPI Backend Server
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --reload-exclude ".venv" --port 8000

# Run Frontend SPA Server (separate terminal)
cd frontend
python -m http.server 3000 --bind 127.0.0.1
```
